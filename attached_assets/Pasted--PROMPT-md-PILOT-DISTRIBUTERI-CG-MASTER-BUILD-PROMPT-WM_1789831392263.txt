## 1. ULOGA AI AGENTA

Ti si senior software architect + full-stack engineer + PostgreSQL/Drizzle expert + UX designer za poslovne aplikacije.

**PILOT DISTRIBUTERI CG**

# 2. GLAVNI PRINCIP APLIKACIJE

Centralna poslovna logika je:

**Dobavljač → Očekivani prijem → Prijem → LOT → Kontrola → Prihvaćeno / HOLD / Odbijeno → Skladište → Zaliha → Porudžbina → Rezervacija → Picking → Utovar → Vozilo → Ruta → Isporuka → Kupac / Povrat**

Paralelno:

**Kontrola → Neusaglašenost → Istraga → Korektivna mera → Verifikacija → Zatvaranje**

Preko svega:

**EVENTS + AUDIT LOGS + TRACEABILITY**

Najvažniji poslovni objekat za sledljivost je:

+
**Backup Responsible Person**

Napraviti tabelu:

`responsibility_assignments`

Kolone:

- id uuid PK
- facility_id FK
- responsibility_type
- primary_user_id FK
- backup_user_id FK
- valid_from

- is_active

Sistem mora moći da evidentira kada je backup aktivirao odgovornost.

Nikad ne menjati količinu zalihe "ručno" bez movement-a.

Svi kritični stock operations moraju biti transaction-safe.

---

## Rezervacija

Ne rezervisati više nego što je dostupno.

Dostupna količina:

`quantity - reserved_quantity`

Provera mora biti serverska.

---

Ne koristiti:

- REJECTED
- EXPIRED
- BLOCKED

osim ako postoji eksplicitna poslovna dozvola.

---

## Vozilo

Ako kritična provera vozila padne:

- vehicle = NOT_READY
- loading = BLOCKED
- kreirati notification
- kreirati task ili NC gde je potrebno

- full delivery
- partial delivery

Primeri:

- QUARANTINE
- RETURN_TO_SUPPLIER
- DESTROY
- REWORK
- ACCEPT_BACK_TO_STOCK

- brisati audit zapise
- praviti samo frontend permission checks
- koristiti fake arrays umesto baze
- duplirati isti business rule na više mesta
- kreirati monolitni React fajl sa celom aplikacijom
- hardkodovati company/facility podatke
- ignorisati status transitions
- izgubiti istoriju promena
